## 0. 一句話版本

**embedding 把「像不像」變成「夾角多小」，推薦與分類都是內積排序；向量空間只有相加、縮放、內積三個動作，應用全是組合；內積只負責粗篩，什麼叫「近」由損失定義。向量做相似，不做推論。**

## 2. 向量當表示（embedding）

**種子：把每個東西（商品、客人、字）各配一支向量，使得「像」＝「夾角小」；之後所有問題都變成內積。**

- 🔄 06 筆記的向量是幾何向量（位置、面朝方向）；ML 應用用的是同一個物件、同一個內積，只多一層：向量當表示（representation / embedding）。缺的是這一層，不是新運算。
- 🔄 為什麼是一列數不是一個數：一個數只能把所有東西排在一條線上，裝不下「A 像 B 又像 C，但 B 不像 C」。
- 🔄 embedding 不是 transformer 的東西，是所有「把離散物件配成向量」的統稱：推薦系統的商品向量、word2vec、LLM 的 token 向量是同一種物件。查表版 = static embedding；transformer 輸出的是看過上下文的 contextual embedding。向量庫只管「找最同向的」，不在乎向量誰產的。
- 🔄 attention 也是內積：query 跟每個 key 做內積當相似度，決定從誰那裡拿資訊。另開線。
- 🔄 向量從哪來：embedding 表本身就是 08 筆記的 w，每個座標都是一個鈕；損失定義「同一張訂單出現的要靠近」，梯度把共現的拉近、不共現的推開。所以「推 B」的底層是統計共現，不是推論。
- 🔄 座標軸沒有名字：第 37 維不是「價格」，是訓練長出的方向，單獨一格讀不出意義；意義只在向量之間的關係裡。想問「這一維代表什麼」= 06 筆記陷阱 5 的新版本（分量當獨立物件）。
- 🔄 神經網路一層 = 矩陣（線性規則紀錄表）把向量送到向量 + 非線性擠壓；最後一層 = h 跟每個類別向量做內積 → logit → softmax → 09 筆記的交叉熵。整個網路的目的：把輸入換成一支「用內積就能答對」的向量。
- ✅ 「用向量做邏輯」一半對：向量做的是「量像不像」，不做「推」（if A then B）；邏輯推論被「相似度排序」取代。（第一則判定，後面復述「高維取內積 = 取關聯」時再確認，用詞「推論」→「比較」。）
- ✅ 高維中取兩支向量的內積就是取它們的關聯（同向共變 × 大小；純關聯用 cos）。

類比失效：「像」≠ 因果、≠ 蘊含。買 A 的人常買 B，可能是替代、配套、或同一批人；向量全壓成「同向」。LLM「看起來像在推理」但不保證——它在相似度空間走，不在證明空間走（趣談 01「AI 與三道牆」段）。

> 濃縮：embedding 把「像不像」變成「夾角多小」；向量不做推論，它只做相似。

## 3. 內積 → 相似度 → 推薦

**種子：向量空間只允許三件事——相加、縮放、內積。所有應用都是這三件事的組合。**

- 🔄 相似度只要夾角：內積除以兩支長度 = cos θ ∈ [−1, 1]，1 同向、0 無關、−1 反向，即 cosine similarity。距離也行：|a − b|² = |a|² + |b|² − 2a·b，長度正規化後距離排名 = cosine 排名；長度不固定時兩者名次不同（內積會偏向長向量 = 熱門商品）。
- 🔄 高維反直覺：維度一多，兩支隨機向量的 cos θ 幾乎必為 0（n 個分量正負隨機、相乘再加互相抵消——01 筆記「大數法則」段）。後果：高維裡 cos 0.3 已是「很有關係」，不要用 2D 直覺讀；「靠近的很多很多」是 2D 直覺。
- ⚠️ 「內積**小**的 B 靠近 A」反了：內積越大越靠近，距離才是越小越近。
- 🔄 推薦 = 給定查詢向量，跟庫裡每支做內積，取最大的前 k。沒有規則說買 A 要推 B，B 被推只因為箭最同向。
- 🔄 向量庫的本體不是存向量，是回答「哪 k 支和這支最同向」而且不用全掃：近似最近鄰（approximate nearest neighbor, ANN）——把空間切成區塊、只掃鄰近區塊，犧牲精確換速度。
- 🔄 用排序不用門檻：系統只問 top-k，不問「誰靠近」。
- 🔄 錨點決定誰靠近：錨 = A 本身 → 替代品；錨 = 客人向量（買過的加總）→ 像這個人買的；錨 = 客人 + 情境 → 更窄。「像」指替代還是搭配不是內積決定的，是 09 筆記那把尺決定的——損失寫「同一張訂單的要靠近」就拉近搭配品。內積只負責量，什麼叫「近」是損失定義的。
- 🔄 兩階段：召回（向量庫 top-k，百萬 → 千，只用內積因為便宜）→ 精排（對候選過大模型，吃幾十個特徵重新打分）→ 規則（剔除已買、缺貨、同類太多）。**內積從來不負責精準**，要求它精準是把粗篩當精排（07 筆記：指標不是目標）。多樣性也是內積：候選之間再做一次，挑「跟查詢近、彼此遠」的。
- 🔄 負內積也是資訊：「買了 A 的人明顯不買 B」。

| 動作 | 意義 | 推薦系統裡的用途 |
|---|---|---|
| 相加 a + b | 疊加 | 客人向量 = 買過的商品向量加總；查詢向量 = 客人 + 情境 |
| 相減 b − a | 從 a 到 b 的差異方向 | king − man + woman ≈ queen；「高價版 − 平價版」是一條價格感方向 |
| 縮放 k·a | 調權重 | 最近買的加重、久遠的衰減 |
| 內積（當相似度） | 對齊程度 × 大小 | 排序 |
| 內積（當讀數） | b 在方向 d 上的座標 | 拿一條有意義的方向去讀每個商品「有多貴」 |
| 矩陣 | 一次做很多內積 | 兩兩相似度表（= 06 筆記協方差矩陣同型）；神經網路一層 |

### 對照：內積 vs cosine 排名（答案已填）

A = (2, 1, −1)，|A| = 2.45。

| 候選 | A·候選 | 長度 | cosine | 內積排名 | cosine 排名 |
|---|---|---|---|---|---|
| B = (3, 2, −1) | 9 | 3.74 | 0.98 | 2 | 1（與 2B 並列） |
| C = (−1, 2, 2) | −2 | 3 | −0.27 | 4 | 3 |
| D = (1, −2, 1) | −1 | 2.45 | −0.17 | 3 | 2 |
| 2B = (6, 4, −2) | 18 | 7.48 | 0.98 | 1 | 1（與 B 並列） |

2B 在內積排名超過 B、在 cosine 排名與 B 並列——這一列就是「內積 vs cosine」的全部差別：長度算不算分。

### 對照：錨點換了，誰往前（答案已填）

軸：動作、解謎、劇情。A = (3, 0, 1)、B = (3, 0, 2)、C = (0, 3, 1)、D = (1, 1, 3)。客人買過 A 和 D，u = A + D = (4, 1, 4)。

| 錨點 | 向量 | ·B | ·C | B：C | ·D |
|---|---|---|---|---|---|
| 只用 A | (3, 0, 1) | 11 | 1 | 11 : 1 | 6 |
| 客人 u | (4, 1, 4) | 20 | 7 | 2.9 : 1 | 17 |

C 在第二列拉近：多拿的分來自解謎軸（1 × 3 = 3）和劇情軸（4 × 1 = 4，原本只有 1）——錨點帶進 D 的偏好。D 自己在第二列內積 17 很高，但已買，被規則剔除。

> 濃縮：內積越大越近（距離才是越小越近）；向量空間只有加、縮放、內積三個動作；靠近的很多就排序取前 k，精準交給下一階段，內積只負責粗篩。

## 4. 記號

```
cos θ = a·b ÷ (|a||b|) ∈ [−1, 1]        cosine similarity；= 相關係數（06 筆記「內積的值是什麼意義」段）
|a − b|² = |a|² + |b|² − 2 a·b          距離與內積的換算；長度正規化後兩種排名一致
sim(a, b) = cos θ；score(u, i) = u·vᵢ    推薦打分；取前 k
u = Σ 買過的 vᵢ（可加權）               客人向量 = 相加 + 縮放
h = σ(Wx + b)                          一層 = 矩陣 + 非線性
logitₖ = vₖ·h；p = softmax(logit)       最後一層 = 跟類別向量做內積 → 09 筆記的交叉熵
```

## 陷阱清單（這條線實際撞到的）

內積本身的陷阱（cos θ 的直角三角形、cos 不存在、要關係不要大小）記在 06 筆記陷阱 7–9；這裡只收應用層。

1. ❌ 內積越小 B 越靠近 A → ✅ 內積越大越靠近；距離才是越小越近 → 為什麼：兩把尺方向相反，|a − b|² = |a|² + |b|² − 2a·b。
2. ❌ 用向量「做邏輯」「做推論」 → ✅ 向量做相似與排序；內積裡藏的邏輯是 AND（逐軸兩邊都要有），不是 if-then → 為什麼：相似 ≠ 因果 ≠ 蘊含。

備註（用詞，不記 ⚠️）：「推論」→「比較」；「向量庫存向量」→ 向量庫的本體是最近鄰索引。
